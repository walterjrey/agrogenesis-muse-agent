## 2. Muse run configuration (fixed in advance, never raised)

Model `muse-spark-1.3` via `https://api.meta.ai/v1`. Limits: cost $2.00, 220 model calls, 660 tool calls, 45 mutations, 200 simulated days, 150 advance requests, 40 consecutive advances, 60 cycles, farm spend 1500 credits, 90 min wall clock, ≤3600 s per advance call, slice = 5 cycles (resumed from persisted state between slices). Termination: `completed` / `model_declared_done` at simulated day 200 (12,000 s). The model reported waiting out the remaining horizon with no eligible harvest/plant/sell action. **The run reached the full horizon and is therefore comparable as complete.** No limit was hit.

Both strategies end with standing, unharvested and unvalued crops; the amounts are not observable.

Realized revenue cannot be split by provenance because sales draw from a fungible inventory; it is reported in aggregate only.

Observed decision differences (descriptive, not causal proof):

- Pre-existing crops were harvested earlier by the baseline (days 45/90/96) than by Muse (days 60/90/120). Muse acted at its own checkpoints (typically 1800 s ≈ 30-day waits); the baseline polls more finely. Earlier cash and earlier replanting are one plausible contributor.
- The baseline planted more fields and included a corn planting (1675.83 kg, the single largest strategy-planted harvest); Muse planted only soybean.
- Muse's late plantings (days ≈120–181) did not mature before the horizon; the baseline also left 4 plantings standing, but harvested its day-95.8 field-4 soybean, a corn planting (day 171.9) and others earlier. Neither end-of-horizon standing crop is valued.
- Muse had one rejected action: `sellHarvest` of 1705.683 kg corn → `insufficient_stock` (act-0008); it re-observed and sold 1705 kg (0.683 kg left). The rejection did not cost credits.
- Neither strategy inspected fields, irrigated or treated pests (water delivered: 0 m³ for both).

## 5. Fairness checks and limitations

Verified/by design:

- Both use the same agent API (`/api/agent/v1`), observe/act/advance scopes, per-game token, revision checking and idempotency keys. The simulator exposes no hidden state to either (`FarmOverview`, field observations, eligible actions only).
- Both start from identical authoritative state (fingerprint equality, above), same seed, market config (constant prices), equipment and horizon (200 days).

Known differences and limitations:

1. **Baseline simplicity.** The baseline is a simple deterministic reference strategy (rules R0–R6 in `src/baseline/policy.ts`, unchanged for this run), not an optimized farmer or human competitor. It never inspects, irrigates or treats pests. It was not tuned after seeing Muse's result.
2. **Pacing.** The baseline polls the clock at fine granularity and has no model latency; Muse chooses its own wait checkpoints. This affects timing of harvests and is part of what is being compared, but is not a pure "decision quality" difference.
3. **Stochasticity.** Muse is stochastic; this is one sample. Another Muse run could differ materially in either direction. Baseline is deterministic (replay identical).
4. **Provenance.** Pre-existing standing crops cannot be told apart from other unknown provenance via the agent API; harvests of such crops are never counted as strategy-generated production. Revenue provenance is aggregate only.
5. **Valuation.** Prices are constant and published; there are no storage limits or price dynamics in the scenario. Inventory value is an estimate, kept separate from realized revenue. Standing crops at the horizon (both strategies) are not valued.
6. **Single scenario.** One seed and one scenario (`established`).
7. **Observation hash.** The controller's recorded start-observation hash is computed with a non-canonical serializer and cannot be compared directly with the baseline's (see §1).
8. **Different PostgreSQL games, same database.** Both games ran in the same isolated database on the same local simulator build.

## 6. Uncertainty

The difference (+1631 vs +2516 credits) is large relative to one run's operational noise, but the sample size is one; cause attribution above is descriptive from action logs, not tested. No claim is made about statistical significance, generalization to other seeds, or about either strategy being "better" in general.

## 7. Reproduce

```
npx tsx scripts\agent-autonomous.ts start --game-id <game> --session-id p5b-muse --enable-mutations \
  --max-cost-usd 2 --max-model-calls 220 --max-tool-calls 660 --max-mutations 45 --max-sim-days 200 \
  --max-advance-requests 150 --max-consecutive-advances 40 --max-cycles 60 --max-farm-spend 1500 \
  --max-wall-minutes 90 --slice-cycles 5 --scenario-name established --scenario-seed 3303 ...
npx tsx scripts\benchmark-report.ts --baseline p5a-baseline --muse p5b-muse --out docs\benchmark\phase5b
```
